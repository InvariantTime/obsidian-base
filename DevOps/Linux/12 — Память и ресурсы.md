# Память и ресурсы

## Память

Linux старается использовать свободную RAM для кэша файлов: полностью «пустая» память не является целью. Поэтому смотрите на `available`, а не только на `free`.

```bash
free -h
cat /proc/meminfo | less
ps -eo pid,user,%mem,rss,vsz,cmd --sort=-rss | head
```

- RSS — страницы процесса, находящиеся в RAM; часть может быть общей с другими процессами.
- VSZ — виртуальное адресное пространство, не фактически занятая RAM.
- swap — место на диске для вытесненных страниц; его использование само по себе не доказывает проблему.

При исчерпании памяти ядро может вызвать OOM killer и завершить процесс. Ищите записи через `journalctl -k -g 'Out of memory|Killed process'` (поддержка `-g` зависит от версии) или `journalctl -k | grep -Ei 'out of memory|killed process'`.

## CPU и load average

```bash
uptime
top
ps -eo pid,pcpu,stat,comm --sort=-pcpu | head
nproc
```

Load average — среднее число задач, которые выполняются/готовы выполняться и задач в непрерываемом ожидании. Его нельзя напрямую считать «процентом CPU». Значение 4 имеет разный смысл на машине с 2 и 32 логическими CPU; высокий load может быть вызван I/O.

## Диск и I/O

```bash
df -hT
df -ih                 # использование inode
du -xhd1 /var 2>/dev/null | sort -h
lsblk -f
```

Если `df` заполнен, а `du` не находит данные, проверьте удалённые, но открытые файлы: `sudo lsof +L1`. Место освободится после закрытия файлового дескриптора; не обнуляйте `/proc/<PID>/fd/...` без понимания приложения.

## Файловые дескрипторы и лимиты

```bash
ulimit -a
ls -l /proc/$$/fd
lsof -p <PID>
cat /proc/<PID>/limits
```

Открытые файлы, сокеты и каналы представлены дескрипторами. Ошибка `Too many open files` может означать утечку в приложении или слишком низкий лимит; простое повышение лимита иногда лишь откладывает отказ. Сначала посмотрите количество и тип открытых объектов.

## Инструменты по слоям

| Вопрос | Первый инструмент |
| --- | --- |
| закончилась RAM? | `free -h`, `journalctl -k` |
| кто грузит CPU? | `top`, `ps --sort=-pcpu` |
| где занято место? | `df`, затем `du` |
| закончились inode? | `df -i` |
| кто слушает порт? | `ss -lntup` |
| какие файлы открыл процесс? | `lsof -p PID`, `/proc/PID/fd` |

Снимайте показатели несколько раз: один снимок не показывает динамику.
