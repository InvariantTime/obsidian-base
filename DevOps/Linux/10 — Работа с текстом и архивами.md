# Работа с текстом и архивами

Многие Linux-инструменты читают поток строк и печатают поток строк. Сильная сторона shell — соединять небольшие программы конвейером.

## Просмотр и фильтрация

```bash
head -n 20 file.log
tail -n 50 file.log
tail -f app.log
grep -nF 'literal.text' app.log
grep -nE 'WARN|ERROR' app.log
cut -d: -f1 /etc/passwd
sort names.txt | uniq -c | sort -nr
```

`grep -F` ищет буквальный текст, `-E` включает расширенные регулярные выражения. `uniq` объединяет только соседние одинаковые строки, поэтому перед ним часто нужен `sort`.

## sed и awk

```bash
sed -n '10,20p' file.txt
sed 's/old/new/g' file.txt         # результат в stdout, файл не меняется
awk -F: '{print $1, $3}' /etc/passwd
awk '$3 >= 1000 {print $1}' /etc/passwd
```

Перед `sed -i` сначала посмотрите результат без `-i` или сделайте резервную копию. Для сложной обработки лучше написать читаемый скрипт на Python, Perl или другом подходящем языке, а не строить хрупкий однострочник.

## xargs и безопасные имена

```bash
find . -type f -name '*.tmp' -print0 | xargs -0 -r rm --
```

Нулевой разделитель сохраняет пробелы и переводы строк в именах. Перед удалением замените `rm` на `printf '%s\n'` или сначала используйте `find ... -print`, чтобы проверить выборку. У `find` также есть `-exec ... {} +`, часто более прямой вариант.

## Архив и сжатие — разные задачи

`tar` собирает дерево файлов в один поток, а gzip/xz/zstd сжимают данные.

```bash
tar -cf project.tar project/
tar -tf project.tar | less
tar -czf project.tar.gz project/
tar -xzf project.tar.gz -C destination/
gzip large.log
gunzip large.log.gz
```

Перед распаковкой незнакомого архива просмотрите список. Архив может содержать абсолютные пути, `..`, символические ссылки и неожиданные права; распаковывайте в отдельный пустой каталог обычным пользователем.

## Контроль целостности

```bash
sha256sum image.iso
sha256sum -c checksums.txt
```

Хеш обнаруживает случайное изменение только при наличии доверенного ожидаемого значения. Сам файл хеша, скачанный рядом с заражённым файлом по тому же каналу, не доказывает подлинность.

## Строка, поле и байт

Большинство классических утилит считает строкой последовательность до `newline`. Это удобно для логов и таблиц, но имя файла в Linux может содержать newline. Поэтому текстовые конвейеры над содержимым и обработка списка файлов — разные задачи.

Кодировка тоже важна. UTF-8 символ может занимать несколько байт; `wc -c` считает байты, `wc -m` — символы с учётом локали.

```bash
printf 'Привет\n' | wc -c
printf 'Привет\n' | wc -m
```

## grep по шагам

```bash
grep -nF -- 'ERROR [42]' app.log
grep -nE -- 'ERROR|WARN' app.log
grep -RIl --include='*.conf' 'listen' ./config
```

- `-n` добавляет номер строки;
- `-F` отключает специальный смысл regex;
- `-E` использует расширенный regex;
- `-I` пропускает бинарные файлы;
- `-l` печатает имена файлов, а не строки;
- `--` завершает опции.

Коды grep: 0 — найдено, 1 — не найдено, 2 — ошибка. Поэтому «не найдено» не обязательно авария.

## Сортировка зависит от локали

```bash
sort names.txt
LC_ALL=C sort names.txt
sort -t, -k2,2n data.csv
```

Во втором примере сортировка идёт по байтовым правилам C locale. `-t,` задаёт разделитель, `-k2,2n` — числовое второе поле. CSV с кавычками и запятыми внутри полей нельзя надёжно разбирать простым `cut`/`awk`; используйте CSV-парсер.

## sed без магии

`sed 's/old/new/'` заменяет первое совпадение в каждой строке; `g` — все совпадения. Разделитель можно сменить:

```bash
printf '%s\n' '/old/path' | sed 's#/old#/new#'
sed -n '/BEGIN/,/END/p' file.txt
```

Не применяйте `sed -i` к важному файлу до проверки вывода и резервной копии. Реализации GNU и BSD sed различаются, особенно синтаксисом `-i`.

## awk как язык записей

```bash
awk -F: 'BEGIN {count=0} $3 >= 1000 {print $1; count++} END {print "total:", count}' /etc/passwd
```

Для каждой строки поля доступны как `$1`, `$2`, вся строка — `$0`; `NF` — число полей, `NR` — номер записи. Одинарные кавычки нужны, чтобы Bash не подставил `$1` до запуска awk.

## Архивирование с проверкой

```bash
tar -czf backup.tar.gz -C "$HOME" Documents
tar -tzf backup.tar.gz | less
mkdir -p ~/restore-test
tar -xzf backup.tar.gz -C ~/restore-test
diff -qr ~/Documents ~/restore-test/Documents
```

Backup не считается проверенным, пока вы не выполнили тестовое восстановление. Архив на том же диске защищает от случайного редактирования, но не от отказа диска, кражи или ransomware.

## Упражнения

1. Посчитайте частоту уровней `INFO`, `WARN`, `ERROR` в учебном логе.
2. Найдите буквальный текст с `[` и сравните `grep -F`/`grep -E`.
3. Создайте архив лаборатории, просмотрите список, восстановите отдельно и сравните.
4. Объясните, почему `for f in $(find ...)` ломает имена с пробелами.
