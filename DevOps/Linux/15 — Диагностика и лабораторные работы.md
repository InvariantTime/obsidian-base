# Диагностика и лабораторные работы

## Универсальный алгоритм

1. Точно описать симптом: что ожидалось, что произошло, когда началось.
2. Определить слой: команда, права, процесс, служба, сеть, диск, память.
3. Собрать состояние до изменения.
4. Проверить одну гипотезу одним минимальным действием.
5. Сравнить результат и записать вывод.
6. Откатить временную диагностику.

Не начинайте с перезагрузки или переустановки: они стирают часть свидетельств и не объясняют причину.

## Карта первичной проверки

| Симптом | Проверки |
| --- | --- |
| command not found | `type -a`, `command -v`, `PATH`, установлен ли пакет |
| Permission denied | `id`, `namei -l <путь>`, `ls -ld`, точка монтирования, ACL |
| сервис не запускается | `systemctl status`, `journalctl -u`, проверка конфигурации |
| порт недоступен | `ss -lntup`, адрес bind, firewall, route, DNS |
| нет места | `df -hT`, `df -i`, `du -x`, `lsof +L1` |
| машина тормозит | `uptime`, `top`, `free`, `ps`, журнал kernel |

`Permission denied` не всегда исправляется `chmod 777`: может отсутствовать `x` у родительского каталога, файловая система быть read-only/noexec, мешать ACL или политика SELinux/AppArmor. Сначала ищите точную проверку, которая отказала.

## Лаборатория 1: дерево файлов

1. Создайте `~/linux-lab/{input,output,bin}`.
2. Создайте файлы с обычным именем, пробелом и именем `-example`.
3. Скопируйте их, используя кавычки и `--`.
4. Создайте символическую и жёсткую ссылки, сравните `stat`.
5. Удалите исходное имя и объясните состояние обеих ссылок.

## Лаборатория 2: права

1. Создайте каталог `shared` и файлы с umask `022` и `077`.
2. Предскажите права до `ls -l`.
3. Измените группу файла на группу, членом которой вы являетесь.
4. Проверьте доступ к каталогам при разных сочетаниях `r`, `w`, `x`.
5. Верните безопасные права после опыта.

## Лаборатория 3: процессы

```bash
sleep 300 &
job_pid=$!
ps -o pid,ppid,stat,cmd -p "$job_pid"
kill -STOP "$job_pid"
ps -o pid,stat,cmd -p "$job_pid"
kill -CONT "$job_pid"
kill -TERM "$job_pid"
wait "$job_pid"
```

Объясните различие shell job ID, PID, сигнала STOP и завершения TERM.

## Лаборатория 4: служба пользователя

Создайте user service `Type=oneshot`, который через `date --iso-8601=seconds` дописывает дату в файл лаборатории. Запустите через `systemctl --user start`, найдите запись в `journalctl --user`, затем добавьте timer. Не используйте root.

## Итоговый проект

Напишите скрипт диагностики, который без `sudo` собирает в каталог: дату, `/etc/os-release`, `uname -r`, `uptime`, `free -h`, `df -hT`, `ip addr`, `ip route`, список failed user units. Скрипт должен:

- создавать новый каталог, не перезаписывая старый;
- цитировать переменные;
- продолжать работу, если необязательная команда отсутствует;
- записывать ошибки отдельно;
- упаковывать результат в `.tar.gz` и печатать SHA-256.
