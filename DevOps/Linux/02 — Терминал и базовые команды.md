# Терминал и базовые команды

## Пути и файлы

```bash
pwd                 # где я?
ls -la              # включая скрытые файлы
cd /var/log         # абсолютный путь
cd ..               # на уровень выше
mkdir -p demo/a     # создать каталог и родителей
touch demo/note.txt # пустой файл или обновление времени
cp source target    # копировать
mv old new          # переименовать или переместить
rm file.txt         # удалить файл без корзины
```

Путь, начинающийся с `/`, абсолютный. Остальные пути отсчитываются от текущего каталога. `.` — текущий каталог, `..` — родительский. Имена с точки обычно скрыты только для вывода `ls` без `-a`.

> [!warning] Удаление
> `rm` обычно не переносит в корзину. Перед `rm -r` проверьте цель через `pwd` и `ls`; не добавляйте `sudo` «на всякий случай».

## Потоки, перенаправления и конвейеры

У программы есть стандартный ввод (stdin, дескриптор 0), вывод (stdout, 1) и ошибки (stderr, 2).

```bash
echo 'hello' > file.txt       # stdout в файл, перезаписывает
echo 'next' >> file.txt       # дописывает
command 2> errors.log         # только stderr в файл
command > all.log 2>&1        # stdout и stderr в один файл
cat file.txt | wc -l          # stdout первой команды = stdin второй
```

Конвейер `|` передаёт данные, а не «успех команды». В Bash `set -euo pipefail` полезен в части скриптов, но заметно меняет обработку ошибок и незаданных переменных — изучите его до бездумного копирования.

## Поиск и просмотр

```bash
less /var/log/syslog            # листать; q — выход
grep -n 'error' app.log         # строка и номер
grep -RIn --include='*.conf' 'listen' /etc
find . -type f -name '*.log'
find . -type f -size +100M
```

Для скриптов не разбирайте вывод `ls`: имена могут содержать пробелы и переводы строк. Используйте `find` и корректные разделители, например `-print0`.

## Как shell находит команду

```bash
type -a cd
type -a ls
command -V grep
```

Имя может оказаться alias, функцией, builtin или файлом из `PATH`. В Bash `hash -r` очищает кэш найденных путей, если программа была перемещена во время сессии.

## Globbing — раскрытие имён

```bash
printf '%s\n' *.md
printf '%s\n' file?.txt
printf '%s\n' image[0-9].png
```

Шаблон раскрывает shell **до** запуска программы. Он не является регулярным выражением. Если совпадений нет, Bash по умолчанию может передать буквальный `*.md`; режимы `nullglob` и `failglob` меняют это. Для буквальной звёздочки используйте кавычки: `'*.md'`.

## Копирование каталогов и сохранение атрибутов

```bash
cp -r source/ destination/
cp -a source/ destination/   # archive: рекурсивно, с метаданными и ссылками
mv -i old new                # спросить перед перезаписью
install -Dm755 app ~/.local/bin/app
```

Слеш в конце и существование каталога назначения могут менять итоговую структуру. Перед большой операцией создайте тестовые каталоги с такой же формой. `cp -a` не гарантирует сохранение всех атрибутов между файловыми системами, если целевая система их не поддерживает.

## Команды, работающие с множеством файлов

```bash
find logs -type f -mtime +30 -print
find logs -type f -mtime +30 -exec gzip -- {} +
```

Сначала выводите список, затем заменяйте `-print` действием. `-exec ... {} +` передаёт несколько найденных путей за запуск и сохраняет границы имён.

## Терминал и управляющие клавиши

- `Ctrl+C` — прервать foreground-задачу сигналом SIGINT;
- `Ctrl+Z` — приостановить её;
- `Ctrl+D` — отправить EOF, если строка ввода пуста;
- `Ctrl+L` — очистить отображение;
- `Ctrl+R` — поиск в истории Bash.

EOF — не символ конца файла на диске, а состояние чтения: программа получает «данных больше нет».

## Общая форма команды

Чаще всего команда выглядит так:

```text
программа [опции] [аргументы]
```

Например, в `ls -l --human-readable /var/log`:

- `ls` — программа;
- `-l` — короткая опция;
- `--human-readable` — длинная опция;
- `/var/log` — аргумент, то есть объект работы.

Это соглашение, а не абсолютный закон: у `tar`, `find`, `git`, `dd` и встроенных команд свой синтаксис. Проверяйте `команда --help` и `man команда`.

## Абсолютный и относительный путь на примере

Допустим, текущий каталог — `/home/alice/project`:

```text
/home/alice/project/
├── README.md
└── src/
    └── app.sh
```

Тогда `src/app.sh`, `./src/app.sh` и `/home/alice/project/src/app.sh` обозначают один файл. Из каталога `/tmp` сработает только абсолютный путь. `~` разворачивается shell в домашний каталог текущего пользователя.

```bash
pwd
realpath ./src/../src/app.sh
basename /home/alice/project/src/app.sh
dirname /home/alice/project/src/app.sh
```

## Создание безопасной учебной структуры

```bash
mkdir -p ~/linux-lab/files/{source,backup}
printf 'first line\nsecond line\n' > ~/linux-lab/files/source/note.txt
cp -v ~/linux-lab/files/source/note.txt ~/linux-lab/files/backup/
ls -lR ~/linux-lab/files
```

Разбор `mkdir -p`: `mkdir` создаёт каталог, `-p` также создаёт недостающих родителей и не считает ошибкой уже существующий каталог. Фигурные скобки — расширение Bash: shell создаёт два аргумента с общей частью пути.

## Что именно делает cp и mv

Если `target` не существует, `cp source target` создаёт файл `target`. Если `target` — существующий каталог, копия окажется внутри под исходным именем. Для каталога нужен `cp -r` или `cp -a`.

`mv` в пределах одной файловой системы обычно переименовывает запись каталога и поэтому работает быстро даже для большого дерева. Между файловыми системами он фактически копирует данные, а затем удаляет источник; операция уже не атомарна целиком.

```bash
cp -iv source.txt destination.txt
mv -iv draft.txt final.txt
```

`-i` просит подтверждение перед перезаписью, `-v` показывает действия. Для скрипта интерактивный вопрос обычно неудобен — там лучше заранее проверять существование цели.

## Потоки на понятном примере

```bash
printf 'orange\napple\norange\n' \
  | sort \
  | uniq -c \
  | sort -nr
```

Каждая программа ничего не знает о соседях: она читает stdin и пишет stdout. Bash создаёт каналы и соединяет их. Ошибки по умолчанию остаются на терминале, потому что stderr не направлен в pipe.

```bash
find /not-existing -type f > files.txt 2> errors.txt
```

В `files.txt` попадут найденные пути, в `errors.txt` — диагностические сообщения.

## Просмотр без случайного изменения

- `cat` удобно печатает небольшой файл целиком;
- `less` открывает большой файл постранично и не изменяет его;
- `head` и `tail` показывают начало/конец;
- `file` пытается определить тип по содержимому;
- `stat` показывает метаданные.

Не открывайте бинарный или огромный файл через `cat` в терминале: вывод может стать нечитаемым. Используйте `file`, `stat`, `less`, `xxd` или специализированную программу.

## Упражнения

1. Создайте каталог с двумя вложенными уровнями одной командой.
2. Создайте файл, имя которого содержит пробел; скопируйте его с кавычками.
3. Перенаправьте обычный вывод и ошибки в разные файлы.
4. Найдите все `.md` внутри лаборатории, не удаляя их.
5. Предскажите результат `pwd` после `cd ..`, затем проверьте.
