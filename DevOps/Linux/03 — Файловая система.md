# Файловая система

Linux показывает почти всё через единое дерево от `/`. Это не значит, что данные лежат на одном диске: разные файловые системы подключаются (монтируются) в точки этого дерева.

| Каталог | Обычно хранит |
| --- | --- |
| `/home` | домашние каталоги обычных пользователей |
| `/root` | домашний каталог root, не корень файловой системы |
| `/etc` | конфигурация системы и служб |
| `/var` | изменяемые данные: логи, кэши, очереди |
| `/usr` | большинство программ и библиотек |
| `/tmp` | временные файлы; содержимое могут очистить |
| `/dev` | представления устройств |
| `/proc` | виртуальные данные о ядре и процессах |
| `/sys` | виртуальные данные об устройствах и ядре |

## Ссылки и метаданные

```bash
stat file                 # владелец, права, inode, время
ln original hard-link     # жёсткая ссылка на тот же inode
ln -s target symbolic     # символическая ссылка, хранит путь
readlink -f symbolic      # разрешённый путь
```

Жёсткая ссылка — второе имя того же файла; обычно её нельзя сделать между разными файловыми системами. Символическая ссылка — отдельный объект с путём; она может стать «битой», если цель переместили.

## Виртуальные файловые системы

`/proc` не является обычным диском: ядро выдаёт там актуальные данные.

```bash
cat /proc/meminfo
cat /proc/$$/status       # $$ подставится в PID текущего shell
df -hT                     # место и тип смонтированных ФС
du -sh ~/Downloads         # размер каталога
findmnt                    # точки монтирования
```

`df` показывает занятость файловой системы, а `du` суммирует доступные по пути файлы; они могут различаться, например, если удалённый файл всё ещё открыт процессом. В `/proc/sys` есть изменяемые параметры ядра — не записывайте туда значения без понимания последствий. См. [документацию procfs](https://docs.kernel.org/filesystems/proc.html).

## Имя, inode и содержимое

Каталог сопоставляет имя с inode. Inode хранит тип, владельца, права, размеры и ссылки на данные, но обычно не само имя. Жёсткие ссылки указывают на один inode; счётчик ссылок виден в `stat` и втором поле `ls -l`.

Удаление через `rm` удаляет имя из каталога. Данные освобождаются, когда не осталось ни жёстких ссылок, ни открытых файловых дескрипторов. Поэтому работающий процесс может продолжить писать в «удалённый» лог, а место на диске не освободится до закрытия файла.

```bash
stat -c 'inode=%i links=%h size=%s' file
ls -li file hard-link
sudo lsof +L1           # удалённые, но открытые файлы
```

## Типы объектов

Первый символ `ls -l` показывает тип:

| Символ | Объект |
| --- | --- |
| `-` | обычный файл |
| `d` | каталог |
| `l` | символическая ссылка |
| `c` | символьное устройство |
| `b` | блочное устройство |
| `p` | именованный канал FIFO |
| `s` | Unix-сокет |

«В Linux всё файл» — полезное приближение, а не буквальное правило. Многие объекты доступны через файловые дескрипторы и похожие операции, но сеть, процессы и устройства имеют собственные системные вызовы и семантику.

## Монтирование скрывает прежнее содержимое

Если файловую систему смонтировать на непустой каталог, прежние файлы не удалятся, но станут невидимы до размонтирования. Это частая причина «пропавших» данных.

```bash
findmnt /var
mountpoint /mnt/data
cat /proc/self/mountinfo | less
```

Bind mount показывает уже существующий каталог в другой точке. Это не копия: изменения видны через оба пути.

## Путь проверяется компонент за компонентом

Для доступа к `/srv/app/data/file` процессу нужен `x` на `/`, `/srv`, `/srv/app`, `/srv/app/data`, а затем требуемое право на `file`. Команда `namei -l /srv/app/data/file` помогает увидеть каждый компонент.

## Временные и псевдофайловые системы

- `tmpfs` хранит данные в памяти и может использовать swap; они не переживают размонтирование/перезагрузку.
- `/proc` экспортирует информацию о процессах и ядре.
- `/sys` описывает устройства, драйверы и параметры ядра.
- `/dev` обычно управляется udev и содержит узлы устройств.
- `/run` хранит runtime-состояние с текущей загрузки: PID-файлы, сокеты, блокировки.

## Почему в Linux нет дисков C: и D:

Linux строит одно дерево от корня `/`. Разделы, флешки, сетевые хранилища и виртуальные файловые системы становятся поддеревьями после монтирования. Например, отдельный раздел может быть подключён к `/home`, а флешка — к `/media/alice/USB`.

```mermaid
flowchart TD
  R[Корень /] --> E[/etc]
  R --> H[/home — отдельный раздел]
  R --> V[/var]
  R --> M[/media/alice/USB — флешка]
  R --> P[/proc — данные ядра]
```

Программа обращается к обычному пути и часто не знает, на каком физическом устройстве лежат данные. Команда `findmnt -T <путь>` показывает файловую систему для конкретного пути.

## Подробная прогулка по каталогам

- `/etc` — системная конфигурация. Здесь обычно текстовые файлы, но менять их нужно по документации конкретного сервиса.
- `/var/log` — журналы, если приложение пишет в файлы; systemd journal может храниться в другом формате.
- `/var/lib` — постоянное изменяемое состояние сервисов, например база пакетов или данные приложения. Это не кэш.
- `/var/cache` — данные, которые в принципе можно восстановить, но нельзя удалять вслепую на работающей системе.
- `/usr/bin` — программы; `/usr/lib` — их библиотеки и данные.
- `/opt` — дополнительное автономное ПО, часто от стороннего поставщика.
- `/srv` — данные, обслуживаемые системой, например содержимое сервера; использование зависит от администратора.
- `/run` — данные текущей загрузки; после reboot они создаются заново.
- `/boot` — ядро, initramfs и файлы загрузчика. Ошибка здесь может сделать систему незагружаемой.

## Что хранит inode

Упрощённо inode содержит:

- тип объекта;
- UID владельца и GID группы;
- права и специальные биты;
- размер и временные метки;
- число жёстких ссылок;
- ссылки на блоки данных.

Имя хранится в каталоге. Поэтому переименование внутри одной файловой системы не переписывает содержимое файла, а две жёсткие ссылки имеют один inode.

```bash
mkdir -p ~/linux-lab/inodes
printf 'data\n' > ~/linux-lab/inodes/original
ln ~/linux-lab/inodes/original ~/linux-lab/inodes/second-name
ls -li ~/linux-lab/inodes
```

Измените `second-name` и прочитайте `original`: содержимое общее. Затем удалите одно имя — второе останется, потому что inode всё ещё имеет ссылку.

## Символическая ссылка по шагам

```bash
ln -s original ~/linux-lab/inodes/symlink
readlink ~/linux-lab/inodes/symlink
readlink -f ~/linux-lab/inodes/symlink
```

Символическая ссылка хранит строку пути. Относительная цель интерпретируется относительно каталога, где лежит ссылка, а не относительно вашего текущего каталога. Это важная причина «битых» ссылок после перемещения.

## Временные метки

`stat` показывает несколько времён:

- mtime — когда менялось содержимое;
- ctime — когда менялись inode-метаданные или содержимое; это не creation time;
- atime — когда объект читали, с учётом политики монтирования;
- birth time — время создания, только если поддерживают файловая система и инструменты.

Переименование обычно меняет ctime, но не mtime содержимого.

## Почему файл можно удалить, пока программа его читает

Открытие возвращает файловый дескриптор — число в таблице процесса. Дескриптор указывает на открытое описание файла, а не повторно ищет имя при каждом чтении. После `rm` имя исчезает, но дескриптор остаётся рабочим. Это удобно для временных файлов, но может незаметно занимать диск.

## Осторожно с /proc и /sys

Чтение обычно используется для диагностики:

```bash
cat /proc/uptime
cat /proc/loadavg
cat /proc/self/status
ls /sys/class/net
```

Запись в часть файлов `/proc/sys` и `/sys` немедленно меняет параметры ядра или устройства. `echo 1 | sudo tee ...` — реальное административное действие, а не редактирование обычного файла. Сначала ищите документацию параметра и способ постоянной настройки.

## Упражнения

1. Для домашнего каталога выполните `findmnt -T "$HOME"` и определите тип ФС.
2. Сравните inode обычного файла, жёсткой и символической ссылок.
3. Через `namei -l` просмотрите каждый компонент пути до файла.
4. Сравните `du -h` и `ls -lh` для файла, созданного `truncate -s 100M sparse-file`.
5. Объясните, почему `/root` не является тем же самым, что `/`.
