# Файловая система

Linux показывает почти всё через единое дерево от `/`. Это не значит, что данные лежат на одном диске: разные файловые системы подключаются (монтируются) в точки этого дерева.

| Каталог | Обычно хранит |
| --- | --- |
| `/home` | домашние каталоги обычных пользователей |
| `/root` | домашний каталог root, не корень файловой системы |
| `/etc` | конфигурация системы и служб |
| `/var` | изменяемые данные: логи, кэши, очереди |
| `/usr` | большинство программ и библиотек |
| `/tmp` | временные файлы; содержимое могут очистить |
| `/dev` | представления устройств |
| `/proc` | виртуальные данные о ядре и процессах |
| `/sys` | виртуальные данные об устройствах и ядре |

## Ссылки и метаданные

```bash
stat file                 # владелец, права, inode, время
ln original hard-link     # жёсткая ссылка на тот же inode
ln -s target symbolic     # символическая ссылка, хранит путь
readlink -f symbolic      # разрешённый путь
```

Жёсткая ссылка — второе имя того же файла; обычно её нельзя сделать между разными файловыми системами. Символическая ссылка — отдельный объект с путём; она может стать «битой», если цель переместили.

## Виртуальные файловые системы

`/proc` не является обычным диском: ядро выдаёт там актуальные данные.

```bash
cat /proc/meminfo
cat /proc/$$/status       # $$ подставится в PID текущего shell
df -hT                     # место и тип смонтированных ФС
du -sh ~/Downloads         # размер каталога
findmnt                    # точки монтирования
```

`df` показывает занятость файловой системы, а `du` суммирует доступные по пути файлы; они могут различаться, например, если удалённый файл всё ещё открыт процессом. В `/proc/sys` есть изменяемые параметры ядра — не записывайте туда значения без понимания последствий. См. [документацию procfs](https://docs.kernel.org/filesystems/proc.html).

## Имя, inode и содержимое

Каталог сопоставляет имя с inode. Inode хранит тип, владельца, права, размеры и ссылки на данные, но обычно не само имя. Жёсткие ссылки указывают на один inode; счётчик ссылок виден в `stat` и втором поле `ls -l`.

Удаление через `rm` удаляет имя из каталога. Данные освобождаются, когда не осталось ни жёстких ссылок, ни открытых файловых дескрипторов. Поэтому работающий процесс может продолжить писать в «удалённый» лог, а место на диске не освободится до закрытия файла.

```bash
stat -c 'inode=%i links=%h size=%s' file
ls -li file hard-link
sudo lsof +L1           # удалённые, но открытые файлы
```

## Типы объектов

Первый символ `ls -l` показывает тип:

| Символ | Объект |
| --- | --- |
| `-` | обычный файл |
| `d` | каталог |
| `l` | символическая ссылка |
| `c` | символьное устройство |
| `b` | блочное устройство |
| `p` | именованный канал FIFO |
| `s` | Unix-сокет |

«В Linux всё файл» — полезное приближение, а не буквальное правило. Многие объекты доступны через файловые дескрипторы и похожие операции, но сеть, процессы и устройства имеют собственные системные вызовы и семантику.

## Монтирование скрывает прежнее содержимое

Если файловую систему смонтировать на непустой каталог, прежние файлы не удалятся, но станут невидимы до размонтирования. Это частая причина «пропавших» данных.

```bash
findmnt /var
mountpoint /mnt/data
cat /proc/self/mountinfo | less
```

Bind mount показывает уже существующий каталог в другой точке. Это не копия: изменения видны через оба пути.

## Путь проверяется компонент за компонентом

Для доступа к `/srv/app/data/file` процессу нужен `x` на `/`, `/srv`, `/srv/app`, `/srv/app/data`, а затем требуемое право на `file`. Команда `namei -l /srv/app/data/file` помогает увидеть каждый компонент.

## Временные и псевдофайловые системы

- `tmpfs` хранит данные в памяти и может использовать swap; они не переживают размонтирование/перезагрузку.
- `/proc` экспортирует информацию о процессах и ядре.
- `/sys` описывает устройства, драйверы и параметры ядра.
- `/dev` обычно управляется udev и содержит узлы устройств.
- `/run` хранит runtime-состояние с текущей загрузки: PID-файлы, сокеты, блокировки.
