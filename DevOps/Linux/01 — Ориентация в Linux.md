# Ориентация в Linux

Строго говоря, Linux — ядро: оно управляет памятью, процессором, устройствами и сетью. В быту «Linux» обычно означает дистрибутив: ядро плюс программы, менеджер пакетов и настройки. Ubuntu, Debian, Fedora и Arch отличаются деталями, но основные идеи общие.

Терминал запускает **оболочку** (shell), часто Bash. Shell читает команду, разворачивает переменные и запускает программу. Поэтому `cd` — встроенная команда: отдельная программа не смогла бы изменить каталог уже работающего shell.

## Узнать систему

```bash
uname -r                 # версия ядра
cat /etc/os-release      # дистрибутив и версия
whoami                   # текущий пользователь
pwd                      # текущий каталог
```

## Root и sudo

`root` — учётная запись с почти неограниченными правами. `sudo команда` запускает одну команду с повышенными правами, если политика системы это разрешает. Это не делает команду безопасной: наоборот, ошибка может затронуть всю систему.

Безопасный порядок: сначала посмотреть объект (`ls -ld <путь>` или `systemctl status <служба>`), затем сформулировать ожидаемый результат, выполнить узкую команду и проверить её эффект.

## Справка

```bash
man ls             # полная справочная страница
ls --help          # краткая справка
man 5 passwd       # формат файла /etc/passwd, раздел 5
apropos permissions # поиск по описаниям man-страниц
```

Номер раздела различает одноимённые сущности: `man 1 passwd` — команда, `man 5 passwd` — формат файла.

## Kernel space и user space

Ядро работает в привилегированном режиме, а обычные программы — в user space. Программа не читает диск и не создаёт процесс напрямую: она обращается к ядру через системные вызовы. Библиотеки и утилиты скрывают большую часть деталей.

```mermaid
flowchart TD
  A[Пользователь] --> B[Shell или GUI]
  B --> C[Программа и библиотеки]
  C --> D[Системные вызовы]
  D --> E[Ядро Linux]
  E --> F[CPU, память, диски, сеть]
```

Если команда вернула `Permission denied`, это часто результат проверки ядром credentials процесса и прав объекта, а не решение конкретной программы. Если процесс «завис», он может ждать устройство через ядро. Эта граница помогает выбирать инструмент диагностики.

## Из чего состоит дистрибутив

- ядро Linux;
- GNU coreutils и другие базовые утилиты;
- libc и системные библиотеки;
- init/service manager, часто systemd;
- менеджер пакетов и репозитории;
- установщик, конфигурация и политика обновлений;
- рабочее окружение, если это desktop-система.

Команды отличаются не только из-за «версии Linux». Например, сеть может настраиваться NetworkManager, systemd-networkd или netplan; firewall — nftables через разные оболочки; пакеты — apt, dnf или pacman. Сначала определяйте дистрибутив и компонент, затем выбирайте инструкцию.

## Архитектура и совместимость

```bash
uname -m
getconf LONG_BIT
file /bin/ls
```

`x86_64` и `aarch64` — разные архитектуры набора команд. Бинарный файл должен соответствовать архитектуре и доступным библиотекам. Скрипт более переносим, но также зависит от интерпретатора, утилит и их реализаций.

## Четыре вопроса перед неизвестной командой

1. Это встроенная команда, alias, функция или исполняемый файл? `type -a <команда>`.
2. От какого пользователя она выполнится? `id`.
3. Какой текущий каталог и какие пути затрагиваются? `pwd`, `ls -ld`.
4. Как проверить результат без изменения системы? `--help`, dry-run, вывод списка целей.

## Разберём один запуск от начала до конца

Пусть вы вводите:

```bash
ls -lh /var/log
```

Происходит примерно следующее:

1. Терминал передаёт строку оболочке Bash.
2. Bash делит строку на слова: `ls`, `-lh`, `/var/log`.
3. Bash определяет, что `ls` — внешняя программа, и находит её через `PATH`.
4. Shell создаёт дочерний процесс и запускает в нём `ls`.
5. `ls` просит ядро открыть каталог `/var/log` и получить метаданные файлов.
6. Ядро проверяет права пользователя, от имени которого работает процесс.
7. `ls` форматирует результат; `-l` включает подробный вид, `-h` — читаемые размеры.
8. Текст отправляется в stdout, терминал отображает его, программа возвращает код завершения.

Эта цепочка объясняет разные ошибки. `command not found` возникает до запуска программы; `Permission denied` часто возвращается ядром при доступе; `No such file or directory` относится к пути или интерпретатору; ненулевой exit code сообщает shell о неуспехе.

## Терминал, shell и консоль — не одно и то же

- **терминальный эмулятор** — окно Ghostty, GNOME Terminal, Konsole и т. п.;
- **shell** — Bash, Zsh, Fish; он разбирает команды;
- **консоль/TTY** — интерфейс ввода-вывода, который может существовать и без графики;
- **команда** — builtin shell, функция или отдельная программа.

Если сменить Bash на Zsh, программы `ls`, `grep` и `git` останутся, но настройки, completion и некоторые правила shell изменятся.

## Где находятся программы

```bash
type -a ls
command -v bash
ls -l "$(command -v bash)"
```

Распространённые каталоги: `/usr/bin` для обычных программ, `/usr/sbin` для административных, `/usr/local/bin` для программ, установленных администратором вне пакетного менеджера, `~/.local/bin` для пользователя. На современных системах `/bin` и `/sbin` часто являются ссылками в `/usr`.

## Как читать приглашение shell

Оно может выглядеть так:

```text
alice@workstation:~/project$
```

Обычно здесь пользователь `alice`, компьютер `workstation`, текущий каталог `~/project`. `$` обычно означает обычного пользователя, `#` — root. Вид приглашения настраивается, поэтому это подсказка, а не механизм безопасности: проверяйте себя командами `id` и `pwd`.

## Мини-практика

Выполните без `sudo`:

```bash
printf 'user: '; whoami
printf 'kernel: '; uname -r
printf 'architecture: '; uname -m
printf 'shell process: '; ps -p $$ -o comm=
printf 'distribution: '; . /etc/os-release && printf '%s\n' "$PRETTY_NAME"
```

Попробуйте объяснить, какая строка относится к ядру, какая — к дистрибутиву, какая — к текущей оболочке. Если `ps -p $$ -o comm=` показывает `bash`, это имя процесса shell; переменная `$SHELL` может означать shell, назначенный учётной записи, а не обязательно текущий процесс.

## Частые заблуждения

- «Ubuntu и Linux — одно и то же». Ubuntu — один из дистрибутивов на ядре Linux.
- «Терминал выполняет команды». Обычно команды разбирает shell внутри терминала.
- «sudo — режим администратора навсегда». Обычно sudo повышает права одной команды и может временно кэшировать подтверждение.
- «Если команда из интернета популярна, она безопасна». Важны ваша система, путь, пользователь и содержимое команды.
