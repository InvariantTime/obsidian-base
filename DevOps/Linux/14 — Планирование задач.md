# Планирование задач

Для периодической команды обычно используют cron или systemd timer. Для долгоживущего процесса нужен service, а не ежеминутный cron, который проверяет, жив ли процесс.

## Cron

```bash
crontab -e
crontab -l
```

Формат пользовательского crontab:

```text
# минута час день-месяца месяц день-недели команда
15 2 * * * /home/alice/bin/backup.sh
```

Cron запускает задачу с ограниченным окружением и другим рабочим каталогом. Используйте абсолютные пути, задавайте `PATH` явно, перенаправляйте stdout/stderr и не полагайтесь на интерактивные alias. У системного `/etc/crontab` есть дополнительное поле пользователя — не переносите строки между форматами без проверки.

## systemd timer

`backup.timer` определяет расписание, а `backup.service` — действие. Это разделение позволяет запускать действие вручную, видеть состояние и журнал.

```ini
# ~/.config/systemd/user/backup.service
[Unit]
Description=Backup documents

[Service]
Type=oneshot
ExecStart=%h/bin/backup.sh
```

```ini
# ~/.config/systemd/user/backup.timer
[Unit]
Description=Daily backup timer

[Timer]
OnCalendar=daily
Persistent=true

[Install]
WantedBy=timers.target
```

```bash
systemd-analyze calendar daily
systemctl --user daemon-reload
systemctl --user enable --now backup.timer
systemctl --user list-timers
journalctl --user -u backup.service
```

`Persistent=true` может запустить пропущенную календарную задачу после следующей активации таймера. Пользовательские сервисы обычно работают только при активном user manager; поведение после выхода настраивается отдельно (`loginctl enable-linger`) и требует осознанного решения.

## Идемпотентность и блокировка

Планировщик может запустить задачу повторно после сбоя или параллельно при долгом выполнении. Скрипт должен безопасно переносить повторный запуск. Для исключения параллельности применяют `flock`, но блокировка не заменяет транзакции и проверку результатов.

Официальная справка: [systemd.timer](https://www.freedesktop.org/software/systemd/man/systemd.timer.html), [systemd.time](https://www.freedesktop.org/software/systemd/man/systemd.time.html).

## Как читать cron-выражение

```text
┌──────── минута (0–59)
│ ┌────── час (0–23)
│ │ ┌──── день месяца (1–31)
│ │ │ ┌── месяц (1–12)
│ │ │ │ ┌ день недели (реализация может принимать 0/7 как воскресенье)
│ │ │ │ │
15 2 * * * команда
```

Это «в 02:15 каждый подходящий день». В cron есть важная особенность взаимодействия day-of-month и day-of-week, которая зависит от стандарта/реализации: читайте `man 5 crontab`, не стройте сложное расписание по памяти.

## Почему cron-скрипт работает вручную, но не по расписанию

- другой `PATH`;
- нет текущего каталога проекта;
- нет интерактивного shell и alias;
- отсутствуют переменные окружения;
- команда ждёт пароль/ввод;
- stdout/stderr не сохраняются туда, где вы смотрите;
- относительный путь указывает не туда.

Скрипт должен задавать рабочий каталог, использовать абсолютные пути там, где нужно, не ждать интерактивного ввода и логировать начало, конец и ошибку.

## Timer и service как две части

Timer отвечает на вопрос «когда активировать», service — «что запустить». Проверяйте отдельно:

```bash
systemctl --user start backup.service
systemctl --user status backup.service
systemd-analyze calendar 'daily'
systemctl --user start backup.timer
systemctl --user list-timers --all
```

Если ручной service не работает, расписание не является причиной. После успешной ручной проверки включайте timer.

## Monotonic и calendar timers

- `OnBootSec=10min` — относительно загрузки;
- `OnUnitActiveSec=1h` — относительно последней активации;
- `OnCalendar=daily` — календарное время;
- `RandomizedDelaySec=` — распределяет массовые одновременные запуски;
- `Persistent=true` — учитывает пропущенное календарное событие после простоя.

Monotonic timer устойчивее к некоторым изменениям wall clock. Calendar timer зависит от timezone, DST и синхронизации времени.

## Задача должна сообщать о неуспехе

Если скрипт всегда возвращает 0, systemd считает его успешным. Проверяйте команды, завершайтесь с ненулевым кодом и не подавляйте stderr без сохранения.

```bash
if ! backup_command; then
  echo 'backup failed' >&2
  exit 1
fi
```

## Упражнение

Создайте user oneshot, который пишет дату и `df -h "$HOME"` в journal. Сначала запустите service вручную, затем timer каждые 10 минут через `OnUnitActiveSec=10min`. После проверки выключите его `systemctl --user disable --now ...`.
