# Окружение и конфигурация shell

## PATH и поиск команды

`PATH` — список каталогов, разделённых двоеточием. Shell ищет исполняемый файл слева направо.

```bash
printf '%s\n' "$PATH" | tr ':' '\n'
type -a python
command -v git
which git            # распространено, но type/command обычно информативнее в shell
```

Не добавляйте `.` в начало `PATH`: тогда случайный файл `ls` в текущем каталоге сможет подменить системную команду. Для собственной программы используйте `./program` или отдельный каталог вроде `~/.local/bin`.

## Основные файлы Bash

| Сценарий | Обычно читается Bash |
| --- | --- |
| login shell | `/etc/profile`, затем один из `~/.bash_profile`, `~/.bash_login`, `~/.profile` |
| интерактивный не-login shell | `/etc/bash.bashrc` или аналог дистрибутива, затем `~/.bashrc` |
| завершение login shell | `~/.bash_logout` |

Точное поведение зависит от режима запуска и дистрибутива. Не копируйте настройки для Zsh в Bash и наоборот.

```bash
alias ll='ls -alF'
export EDITOR=nvim
source ~/.bashrc
```

Alias удобен для интерактивной работы, но в скриптах используйте функции или программы. Перед изменением конфигурации сделайте копию; синтаксическую проверку Bash-скрипта выполняет `bash -n file.sh`.

## История и секреты

```bash
history | tail
history -d <номер>
```

Удаление строки из history не гарантирует удаление секрета: он мог попасть в список процессов, журнал CI, аудит, резервную копию или удалённую систему. Если секрет оказался в командной строке, считайте его скомпрометированным и замените. Для пароля используйте безопасный интерактивный ввод или файловый дескриптор, который поддерживает программа.

## Локаль и время

```bash
locale
date --iso-8601=seconds
timedatectl
```

Локаль влияет на сортировку, регистр, формат чисел и сообщения. В воспроизводимом скрипте иногда уместно `LC_ALL=C`, но это также меняет правила обработки текста; применяйте локально к одной команде: `LC_ALL=C sort file`.

## Переменная shell и переменная окружения

```bash
local_only='visible in this shell'
export inherited='visible to children'
bash -c 'printf "local=<%s> inherited=<%s>\n" "$local_only" "$inherited"'
```

Новый Bash не увидит `local_only`, но унаследует `inherited`. `export` помечает имя для передачи при запуске дочерних процессов. Уже работающие процессы не получают последующие изменения.

Окружение — не безопасное секретное хранилище: переменные доступны процессу, могут попасть в дамп, диагностику или конфигурацию оркестратора.

## PATH по шагам

При `PATH=/home/alice/.local/bin:/usr/local/bin:/usr/bin` запрос `tool` проверяется слева направо. Если найден не тот файл:

```bash
type -a tool
printf '%s\n' "$PATH" | tr ':' '\n'
ls -l "$(command -v tool)"
```

Пустой элемент PATH означает текущий каталог в некоторых реализациях (`::` или двоеточие в начале/конце) и создаёт риск подмены. Не добавляйте непроверенные writable-каталоги раньше системных.

## Файлы запуска: почему настройка «не сработала»

`~/.profile` и `~/.bashrc` читаются в разных режимах. Графический вход, SSH, терминал и `bash -c` могут создавать разные типы shell. Сначала узнайте:

```bash
printf 'flags=%s\n' "$-"       # содержит i для interactive
shopt -q login_shell && echo login || echo non-login
ps -p $$ -o args=
```

Обычные alias и prompt помещают в `.bashrc`. Переменные окружения для login-сеанса часто задают в `.profile`, но desktop может иметь дополнительные механизмы. Не решайте проблему добавлением одной строки во все файлы — получите дублирование и неожиданный порядок.

## Source против запуска

```bash
./script.sh
bash script.sh
source script.sh
```

- `./script.sh` требует execute bit и использует shebang;
- `bash script.sh` явно запускает файл новым Bash, execute bit не обязателен;
- `source` выполняет команды в текущем shell и способен изменить его каталог, переменные и trap.

Источник через `source` должен быть доверенным кодом. Не source-файл только ради «подгрузить значения», если он получен извне.

## Prompt и exit code

Переменная `PS1` формирует приглашение. Избыточно сложная команда в prompt выполняется перед каждым вводом и способна замедлить terminal. Если prompt показывает ветку Git или exit code, это функция shell, а не свойство терминала.

## Упражнения

1. Создайте локальную и экспортированную переменные; сравните их в дочернем Bash.
2. Найдите все реализации `python` через `type -a`.
3. Определите, login ли текущий shell.
4. Создайте временную функцию в shell и убедитесь, что дочерний Bash её не наследует по умолчанию.
