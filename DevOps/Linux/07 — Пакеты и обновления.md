# Пакеты и обновления

Пакетный менеджер устанавливает программы вместе с зависимостями, отслеживает файлы и проверяет подписи репозиториев. Не смешивайте команды разных семейств дистрибутивов.

| Семейство | Менеджер | Примеры |
| --- | --- | --- |
| Debian/Ubuntu | `apt` | `sudo apt update`, `sudo apt upgrade`, `apt search <имя>` |
| Fedora/RHEL | `dnf` | `sudo dnf upgrade`, `dnf search <имя>` |
| Arch | `pacman` | `sudo pacman -Syu`, `pacman -Ss <имя>` |

`apt update` обновляет список доступных пакетов, а `apt upgrade` устанавливает обновления. Похожее разделение есть в других менеджерах, но флаги и их последствия различаются.

```bash
sudo apt update
apt list --upgradable
sudo apt upgrade
```

Перед обновлением рабочей или удалённой машины убедитесь, что есть резервная копия и доступ к консоли. Обновление ядра может потребовать перезагрузки; после неё проверьте `uname -r` и критичные сервисы.

Не запускайте `curl ... | sudo sh`, не добавляйте случайные сторонние репозитории и не подтверждайте удаление пакетов, не прочитав список последствий.

## Репозиторий, пакет и база состояния

Репозиторий публикует метаданные и пакеты. Менеджер разрешает зависимости, проверяет подписи метаданных/пакетов и записывает установленное состояние. Низкоуровневые инструменты (`dpkg`, `rpm`) работают с отдельными пакетами, а `apt`/`dnf` дополнительно работают с репозиториями и зависимостями.

```bash
apt show curl
apt-cache policy curl
dpkg -S /usr/bin/curl
dpkg -L curl | less
```

На Fedora аналоги включают `dnf info`, `dnf repoquery` и `rpm -qf`. Всегда смотрите справку вашей версии.

## Поиск происхождения файла и команды

Если команда есть:

```bash
command -v curl
dpkg -S "$(command -v curl)"
```

Если команды нет, поиск по имени пакета не всегда совпадёт с именем программы. Используйте поиск менеджера пакетов или индекс содержимого репозитория, доступный дистрибутиву.

## Конфигурация при обновлении

Пакетный менеджер старается не затереть локально изменённую конфигурацию, но может запросить выбор версии или создать дополнительные файлы (`.dpkg-dist`, `.rpmnew` и аналоги). После обновления сравнивайте конфигурацию и проверяйте сервисы. Удаление пакета и purge — разные операции в Debian-семействе: purge дополнительно удаляет пакетную системную конфигурацию, но не гарантирует удаление пользовательских данных.

## Стороннее ПО

Предпочтительный порядок:

1. официальный репозиторий дистрибутива;
2. официальный репозиторий разработчика с отдельным ключом и ограниченным `signed-by`;
3. sandboxed формат (если соответствует угрозам и требованиям);
4. вручную установленный бинарник с проверкой подписи/хеша и понятным механизмом обновления.

Добавление ключа как глобально доверенного расширяет область доверия. Не используйте устаревшие инструкции с безусловным `apt-key add`; следуйте документации текущей версии дистрибутива.

## Обновление production-системы

- прочитать changelog критичных компонентов;
- проверить резервную копию и план отката;
- обновить тестовую среду;
- учесть перезапуск сервисов и необходимость reboot;
- проверить failed units, журнал, порты и прикладные health checks;
- не выполнять необратимую миграцию БД без отдельного плана.

## Почему лучше пакетный менеджер

Если вручную скопировать программу в `/usr/bin`, система не знает, откуда она появилась, какие файлы ей принадлежат и как получать исправления. Пакет описывает версию, архитектуру, зависимости, контрольные суммы, скрипты установки и список файлов. Менеджер хранит базу установленного состояния.

Это не делает любой пакет безопасным: доверие переносится на репозиторий, его ключи и процесс сборки. Поэтому источник важнее красивого имени пакета.

## Пошаговое обновление Debian/Ubuntu

```bash
sudo apt update
apt list --upgradable
apt changelog <package>     # доступность зависит от пакета/репозитория
sudo apt upgrade
```

1. `apt update` скачивает метаданные, но не обновляет установленные программы.
2. `apt list --upgradable` показывает кандидатов.
3. `apt upgrade` строит план и просит подтверждение.
4. Вы читаете список установки, обновления и удаления до ответа `Y`.

`full-upgrade` способен удалять пакеты для разрешения зависимостей и потому требует ещё более внимательного чтения плана.

## Установка и удаление

```bash
apt search '^tree$'
apt show tree
sudo apt install tree
dpkg -L tree | less
sudo apt remove tree
```

`apt search` может вернуть похожие имена; перед установкой читайте описание, источник и версию. `apt remove` может оставить системную конфигурацию. `autoremove` предлагает зависимости, которые считаются больше не нужными, но список также нужно проверять.

## Кто создал этот файл

```bash
command -v ssh
dpkg-query -S /usr/bin/ssh
dpkg-query -W -f='${Package} ${Version}\n' openssh-client
```

Это полезно, если файл повреждён, версия неожиданна или нужно найти документацию пакета. Файл из `/usr/local/bin` часто не принадлежит пакету дистрибутива.

## Snap, Flatpak и контейнеризированные форматы

Такие форматы могут поставлять собственные зависимости и sandbox, но не являются автоматически безопасными или более лёгкими. У них отдельные команды обновления, разрешения и хранилище. Разберитесь, какую именно копию запускает `type -a app` и кто отвечает за обновление.

## Что делать после обновления

```bash
systemctl --failed
journalctl -p err -b
uname -r
```

Некоторые процессы продолжают использовать старую библиотеку до перезапуска. Дистрибутив может предоставить инструмент для поиска таких процессов. Перезагрузка нужна не после каждого пакета, но новое ядро начинает работать только после неё.

## Частые ошибки

- Смешать репозитории разных выпусков дистрибутива.
- Ставить пакет по инструкции для другой системы.
- Удалить lock-файл, когда другой package manager действительно работает.
- Прервать установку питанием и затем повторять команды без чтения ошибки.
- Предполагать, что версия из дистрибутива «уязвима» только из-за старого номера: исправления могут быть backport без смены upstream major/minor.

## Упражнение без установки

Найдите пакет программы `ls`, выведите его версию и список файлов. Затем найдите package candidate для `curl` и источник репозитория. Ничего не устанавливайте — цель в чтении базы пакетов.
