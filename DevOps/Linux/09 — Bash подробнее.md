# Bash подробнее

Shell — не просто окно терминала. Терминал передаёт ввод и отображает вывод, а Bash разбирает текст команды. Упрощённо он читает строку, выполняет подстановки, формирует аргументы, применяет перенаправления и запускает встроенную команду или программу.

## Команда и аргументы

```bash
printf '%s\n' one 'two words' "home=$HOME"
```

Здесь `printf` получает четыре аргумента. Пробел обычно разделяет аргументы; кавычки сохраняют пробел внутри одного аргумента.

| Запись | Что делает Bash |
| --- | --- |
| `'text $HOME'` | ничего не подставляет |
| `"text $HOME"` | подставляет переменные, сохраняет результат одним аргументом |
| `$HOME` | подставляет значение, затем возможны разбиение и glob |
| `*.log` | разворачивает в подходящие имена файлов |
| `$(command)` | подставляет stdout команды без завершающих переводов строк |

Почти всегда переменные с путями заключают в двойные кавычки: `cp -- "$source" "$target"`. `--` сообщает многим утилитам, что дальше идут операнды, даже если имя начинается с `-`.

## Переменные и окружение

```bash
name='Alice'             # переменная текущего shell
export APP_ENV=dev       # попадёт в окружение дочерних процессов
printf '%s\n' "$name"
env | sort | less
unset APP_ENV
```

Дочерний процесс наследует экспортированные переменные, но не может изменить окружение родительского shell. Именно поэтому скрипт запускают через `source script.sh`, только если хотят выполнить его команды внутри текущего shell — это также означает, что скрипт способен изменить `cd`, переменные и функции текущей сессии.

## Коды выхода и условия

Ноль означает успех, ненулевое значение — ошибку или другой специальный результат.

```bash
grep -q 'ready' app.log
printf 'exit=%s\n' "$?"

if grep -q 'ready' app.log; then
  echo 'application is ready'
else
  echo 'not ready'
fi
```

`cmd1 && cmd2` запускает вторую команду после успеха первой; `cmd1 || cmd2` — после неуспеха. Это управление по коду выхода, а не передача данных.

## Функции и минимальный скрипт

```bash
#!/usr/bin/env bash
set -u

greet() {
  local name=${1:-world}
  printf 'Hello, %s!\n' "$name"
}

greet "${1:-}"
```

`$0` — имя скрипта, `$1` — первый аргумент, `$#` — число аргументов, `"$@"` — все аргументы с сохранением границ. Проверяйте входные данные и цитируйте подстановки. `set -e` не является универсальной обработкой ошибок: у него есть исключения в условиях, списках команд и конвейерах. Для важных действий лучше проверять результат явно и печатать понятное сообщение.

## Job control

`Ctrl+C` обычно посылает foreground-группе `SIGINT`, `Ctrl+Z` — `SIGTSTP`. После остановки используйте `jobs`, `bg %1`, `fg %1`. Фоновая задача всё ещё связана с терминалом; для долгоживущей службы используйте systemd, а не случайный `nohup`.

Практика: создайте скрипт, который принимает каталог, проверяет его существование, считает файлы и возвращает ненулевой код при ошибке.

## В каком порядке Bash обрабатывает строку

Полный алгоритм имеет исключения, но новичку полезна модель:

1. Bash читает синтаксис: команды, `|`, `&&`, `;`, перенаправления.
2. Выполняет раскрытия: фигурные скобки, `~`, параметры, `$(...)`, арифметику.
3. Для незакавыченных результатов делает word splitting и pathname expansion.
4. Применяет перенаправления.
5. Выполняет builtin/функцию или запускает внешнюю программу.

Поэтому кавычки имеют значение до запуска программы. Программа не узнаёт, были ли аргументы написаны в кавычках — она получает готовый массив строк.

## Одинарные, двойные и отсутствие кавычек

```bash
name='two words'
printf '<%s>\n' $name
printf '<%s>\n' "$name"
printf '<%s>\n' '$name'
```

Первый вызов обычно печатает два аргумента, второй — один, третий — буквальный `$name`. Привыкайте писать `"$variable"`, кроме случаев, где разбиение действительно задумано.

## Массивы вместо строк с аргументами

Нельзя надёжно хранить сложную команду в строке и запускать `$command`. Используйте массив:

```bash
args=(grep -n --fixed-strings)
pattern='two words'
"${args[@]}" -- "$pattern" file.txt
```

Каждый элемент массива остаётся отдельным аргументом. Не применяйте `eval` к данным пользователя: оно повторно интерпретирует текст как код shell.

## Позиционные аргументы

```bash
printf 'script=%s\n' "$0"
printf 'count=%s\n' "$#"
for argument in "$@"; do
  printf 'arg=<%s>\n' "$argument"
done
```

`"$@"` разворачивается в отдельный аргумент на каждый исходный параметр. `"$*"` объединяет их одной строкой; для передачи дальше почти всегда нужен `"$@"`.

## Проверки файлов

```bash
if [[ -f $path ]]; then
  echo 'regular file'
elif [[ -d $path ]]; then
  echo 'directory'
else
  echo 'missing or another type' >&2
fi
```

Внутри `[[ ... ]]` Bash предоставляет безопасный синтаксис условий. Существование после проверки может измениться до использования — в security-critical коде избегайте модели «проверить, потом открыть» и полагайтесь на атомарные операции приложения.

## Trap и временный каталог

```bash
work_dir=$(mktemp -d)
cleanup() {
  rm -rf -- "$work_dir"
}
trap cleanup EXIT
```

Это допустимо только потому, что путь создан `mktemp`, сохранён в отдельной переменной и заключён в кавычки. Не подставляйте в рекурсивное удаление непроверенный пользовательский путь. Trap EXIT запускает очистку при обычном выходе и многих ошибках, но не после SIGKILL или аварии питания.

## Отладка скрипта

```bash
bash -n script.sh           # синтаксис без выполнения
bash -x script.sh arg       # трассировка; может раскрыть секреты
shellcheck script.sh        # статический анализ, если установлен
```

Не включайте `set -x` рядом с токенами и паролями. Печатайте понятные сообщения в stderr и возвращайте различимые коды там, где вызывающая сторона должна реагировать.

## Упражнение

Напишите `count-files.sh`: принимает ровно один каталог, при ошибке печатает usage в stderr и код 2, считает обычные файлы без разбора `ls`, корректно работает с пробелами в пути. Проверьте `bash -n` и ShellCheck.
