# Bash подробнее

Shell — не просто окно терминала. Терминал передаёт ввод и отображает вывод, а Bash разбирает текст команды. Упрощённо он читает строку, выполняет подстановки, формирует аргументы, применяет перенаправления и запускает встроенную команду или программу.

## Команда и аргументы

```bash
printf '%s\n' one 'two words' "home=$HOME"
```

Здесь `printf` получает четыре аргумента. Пробел обычно разделяет аргументы; кавычки сохраняют пробел внутри одного аргумента.

| Запись | Что делает Bash |
| --- | --- |
| `'text $HOME'` | ничего не подставляет |
| `"text $HOME"` | подставляет переменные, сохраняет результат одним аргументом |
| `$HOME` | подставляет значение, затем возможны разбиение и glob |
| `*.log` | разворачивает в подходящие имена файлов |
| `$(command)` | подставляет stdout команды без завершающих переводов строк |

Почти всегда переменные с путями заключают в двойные кавычки: `cp -- "$source" "$target"`. `--` сообщает многим утилитам, что дальше идут операнды, даже если имя начинается с `-`.

## Переменные и окружение

```bash
name='Alice'             # переменная текущего shell
export APP_ENV=dev       # попадёт в окружение дочерних процессов
printf '%s\n' "$name"
env | sort | less
unset APP_ENV
```

Дочерний процесс наследует экспортированные переменные, но не может изменить окружение родительского shell. Именно поэтому скрипт запускают через `source script.sh`, только если хотят выполнить его команды внутри текущего shell — это также означает, что скрипт способен изменить `cd`, переменные и функции текущей сессии.

## Коды выхода и условия

Ноль означает успех, ненулевое значение — ошибку или другой специальный результат.

```bash
grep -q 'ready' app.log
printf 'exit=%s\n' "$?"

if grep -q 'ready' app.log; then
  echo 'application is ready'
else
  echo 'not ready'
fi
```

`cmd1 && cmd2` запускает вторую команду после успеха первой; `cmd1 || cmd2` — после неуспеха. Это управление по коду выхода, а не передача данных.

## Функции и минимальный скрипт

```bash
#!/usr/bin/env bash
set -u

greet() {
  local name=${1:-world}
  printf 'Hello, %s!\n' "$name"
}

greet "${1:-}"
```

`$0` — имя скрипта, `$1` — первый аргумент, `$#` — число аргументов, `"$@"` — все аргументы с сохранением границ. Проверяйте входные данные и цитируйте подстановки. `set -e` не является универсальной обработкой ошибок: у него есть исключения в условиях, списках команд и конвейерах. Для важных действий лучше проверять результат явно и печатать понятное сообщение.

## Job control

`Ctrl+C` обычно посылает foreground-группе `SIGINT`, `Ctrl+Z` — `SIGTSTP`. После остановки используйте `jobs`, `bg %1`, `fg %1`. Фоновая задача всё ещё связана с терминалом; для долгоживущей службы используйте systemd, а не случайный `nohup`.

Практика: создайте скрипт, который принимает каталог, проверяет его существование, считает файлы и возвращает ненулевой код при ошибке.
